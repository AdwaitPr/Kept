# Kept Web Full-Stack Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-grade, real-time synchronized Next.js 15 web application for Kept that shares the exact domain model, lifecycle, and data state with the Android application, run it in localhost to capture DOM screenshots, and update the GitHub repository.

**Architecture:** A modern web app built with Next.js 15 (App Router, React 19) and Tailwind CSS / shadcn/ui that interfaces with Supabase (PostgreSQL + Realtime WebSockets CDC). Features an offline/local-first state fallback with optimistic UI updates, mirroring the Android app's `PENDING`, `RENEGOTIATED`, `KEPT`, and `RELEASED` lifecycle.

**Tech Stack:** Next.js 15, React 19, TypeScript, Tailwind CSS, shadcn/ui, Lucide React, Supabase JS SDK, Vitest / Testing Library.

**Spec:** [kept_fullstack_architecture.md](file:///Users/adwaitpratapsingh/.gemini/antigravity/brain/d685df19-7c11-473e-abaf-445572539bf0/kept_fullstack_architecture.md)

## Global Constraints

- **Identical Domain Model**: Core status must be exactly `PENDING`, `RENEGOTIATED`, `KEPT`, `RELEASED`. No generic "todo", "done", or "in progress" states.
- **Time Representation**: All timestamps must be stored and computed in UTC epoch milliseconds, formatted to local browser timezone using `Intl.DateTimeFormat`.
- **Zero Contact Scraping**: Recipient autocomplete operates solely on historical commitment data.
- **Localhost Readiness**: Web app must run seamlessly on `http://localhost:3000` with instant hot-reload and seed demo data even before external Supabase credentials are wired.
- **Documentation & Screenshots**: Must capture live rendered DOM screenshots of all key screens (Ledger, Quick Capture, Renegotiation, EOD Review, History) and embed them into the project `README.md`.

## Review Focus

1. **Renegotiation deadline validation**: A revised deadline must be strictly greater than the current timestamp and must record an audit entry.
2. **Timezone consistency**: A commitment due at 5:00 PM local time must maintain its exact UTC millisecond epoch across both Android and Web.
3. **Empty state handling**: When no commitments exist in Overdue, Today, or Upcoming, show calm, non-judgmental ledger states.
4. **Optimistic status closure**: Clicking "Kept" or "Released" must immediately update the UI state without delay, rolling back only on network failure.
5. **Multi-device UUID collision safety**: All records generated by Web and Android must use standard RFC4122 UUIDv4 strings.
